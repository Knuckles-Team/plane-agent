| `CONN-PLANE-AGENT-CONNECTOR-CONTENT-R003` | **Declared ingest sources.** `plane_agent/connector_sources.py` declares the connector `plane-mcp` with `source_meta`. The server serves the declaration live at `connector://resources`. It declares three sources. `projects` reads `plane_list_projects` as `SoftwareProject`. `work-items` reads `plane_list_work_items` as `Issue` and maps to `WorkItem`. `project-states` reads `plane_list_states` as `ProjectState`. `work-items` and `project-states` carry `for_each` on `projects`: the runner calls the tool once per project and passes the project `id` as `project_id`. Every tool is read-only. Every record type has a `schema_mappings` entry. The package requires `scion-sdk>=0.4.3`. The ingest binding in `plane_agent/kg_ingest.py` takes its connector from `connector_name("plane_agent")`, so it equals the fleet name `plane-mcp`; the source mapping `plane_agent/ontology/mappings/source.yaml` names the same connector. Proving tests: `tests/test_ingest_sources.py`, `tests/test_kg_ingest.py::test_ingest_binding_connector_is_the_sdk_connector_identity`. | The declaration names a read-only tool for each source, maps `work-items` to `Issue` with `state`, and fans out per project. |
| `CONN-PLANE-AGENT-CONNECTOR-CONTENT-R004` | **Competency-question paths.** `plane.ttl` declares `state` on `Issue` (the work-item type that the shared `WorkItem` parent carries `priority` and `state` for); `Workspace` extends `Namespace`, `Cycle` extends `Iteration`, `PlaneModule` (the Plane module, distinct from the code `Module`) extends `Collection` and `ProjectState` extends `Concept`; no `schema_mappings` entry has a null `ontology_class`. Proving test: `tests/test_cq_paths.py`. | The test finds `state` and `priority` on `Issue` and no null mapping. |
